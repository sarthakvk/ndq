# Parser Design

## I/O Contract

### Input

The parser takes the token list generated by the lexer from the user's input.

### Errors

The parser reports a syntax error if the input does not conform to the [grammar](#grammar).

### Output

On success, the parser returns an abstract syntax tree (AST). This confirms that the query is syntactically valid and conforms to the [grammar](#grammar).

## Grammar

```ebnf
(* Precedence: () > ! > & > | *)
query = or_expr

or_expr = and_expr, {"|", and_expr}

and_expr = not_expr, {"&", not_expr}

not_expr = predicate | ("!", not_expr)

predicate = comp | "(", or_expr, ")"

(* Any combination of fields and values is valid; this makes value <op> value and field <op> field valid too. *)
comp = term, op, term

term = (field | value)

op = "=" | "!=" | "<" | "<=" | ">" | ">="

(* Allow specifying nested fields with . notation. *)
field = identifier, {".", identifier}

value = string | number | "true" | "false" | "null"
```
